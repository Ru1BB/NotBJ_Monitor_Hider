# 京途 · 北京周边探头地图

## 摄像头区域避让路线规划

点击首页“路线”，输入地点名称，使用高德地点搜索并从候选结果选择起点或终点（仅支持北京周边）；也可在地图选择 A/B 点或输入高德坐标（经度,纬度）。两端均提供“当前位置”，点击后重新获取浏览器定位并转换为高德坐标，不会使用手动查询中心冒充当前位置；起点另保留“使用查询中心”。地点搜索使用现有 Web JS Key 和安全代理/会话密钥，关键词在停止输入 350 毫秒后发送至高德，每次最多展示 6 项；地图选点和坐标输入不调用地点搜索。选择地点后编辑名称必须重新选择结果；移动不会自动改变已选路线端点。选择后地图立即显示起点 A、终点 B 及地点名称，并自动调整视野显示已选端点。更换地点会替换标记，清空或编辑未选名称时移除对应标记；清除路线或规划失败仍保留有效端点。点击“规划路线”后，首次规划一条普通驾车路线，本地按当前进京证与高峰状态筛选全量已加载原始摄像头，检查受限点位坐标与整条路线线段的距离，将 40 米内点位周围的方形区域批量累积到下一次请求；同坐标记录只占一个区域。地图分组中心和附近半径不参与计算。

每轮最多向本站请求 5 次，最多对应 5 次新增高德调用；缓存命中也占一轮，避免循环。单轮 45 秒后不再追加请求；单次上游超时 12 秒。达到次数或时间限制，可手动“继续尝试”，保留起终点、点位快照、历史避让和重复路线记录；不会因移动自动重算。区域上限、重复路线、无新增区域或接口错误会停止，不把失败解释为“距离太远”。只有通过检查的路线才以绿色显示；未通过时不绘制行驶路线或展示其距离/耗时，地图保留可打开详情的失败提示。区域刚满但本轮已新增约束时，仍先尝试一次这些约束；后续检查无可新增区域才停止。

两项额度节省措施：相同起终点、固定策略及避让区域的成功响应在服务端缓存 60 秒，最多 100 条；相同在途请求合并。前端规划时锁定输入与按钮，函数也拒绝重复提交。缓存仅属于单进程/Worker isolate；重启后丢失，不提供跨实例去重。页面显示新增高德请求数及缓存/并发复用次数；上游错误仍可能计入高德调用，页面计数只统计成功取得响应的规划轮次，不作为账单依据。

服务端新增配置（项目不会自动读取 `.env`，需通过运行环境加载）：

```powershell
$env:AMAP_WEB_SERVICE_KEY = '自己的高德 Web 服务 API Key'
$env:AMAP_ROUTE_MAX_REGIONS = '32'
node server.js
```

`AMAP_WEB_SERVICE_KEY` 与底图的 Web JS Key 类型不同，不可混用；它仅保存在服务端，不由 `/api/config` 返回。Node 与 Worker 都调用 `POST /api/route`，上游使用高德 `/v5/direction/driving` 的表单 POST、固定速度优先策略和完整路线坐标。官方文档明确最大支持 32 个避让区域、每个最多 16 个顶点、单区不超过 81 平方公里；本站按最大能力设置 `AMAP_ROUTE_MAX_REGIONS=32`，不再把文档中的“默认支持 1 个”当作本站上限。管理员可显式降低本站上限（1–32）。2026-11-14 已用服务器当前 Web 服务 Key 实测一次 32 个区域的表单 POST，返回 status=1 / infocode=10000 及可用路线；这证明请求被接受，不代替每次返回路线的本地逐段检查。缺少配置会显示未启用，不以底图成功代替规划权限验收。参见[高德路径规划 2.0 文档](https://lbs.amap.com/api/webservice/guide/api/newroute)。

来源坐标、点位完整性、车道/高架层级仍未核验；40 米是工程检查阈值，非实测拍摄范围。成功只表示未接近当前数据中的已知点位，不保证没有摄像头或允许通行。本功能提供网页路线预览，不提供语音播报、偏航重算，也不将避让约束交给高德 App。上线前须用有效 Key 核验账号避让权限、真实响应、地图渲染及若干现场路线。

首版移动端优先 Web 应用：高德地图、浏览器定位、手动选点、附近探头列表及来源详情。附近距离计算在浏览器内完成。路线规划会把起终点及避让区域经本站发送给高德；本站只作短时内存缓存，不写入数据库或位置日志。

## 部署方式

这是一个带 Node.js 后端的 Web 应用：后端负责读取并缓存来源数据、提供接口和高德安全代理，前端是 `public/` 中的静态页面。适合有 Node.js 运行环境的服务器或支持长驻 Node.js 服务的平台；不能仅上传 `public/` 到纯静态网站托管。页面资源、API 和高德代理使用相对路径，支持域名根目录或 `/jingtu/` 等子路径；子路径反向代理需去掉前缀再转发给 Node，并将不带末尾斜杠的入口重定向到带斜杠入口。

## 本机预览（Windows PowerShell）

需要 Node.js 20 或更高版本，无第三方 npm 依赖。在本目录打开 PowerShell：

```powershell
node server.js
```

打开 http://127.0.0.1:3000，在页面输入已配置 Key 对应的高德安全密钥，然后点击加载地图。密钥按 Key 关联保存在当前标签页的 `sessionStorage`，刷新会自动恢复，不写入长期 `localStorage`。通常关闭标签页后会话结束；浏览器恢复会话可能恢复这些数据，可在“设置 → 地图密钥”中主动清除。浏览器禁用存储时仍可加载，但刷新需重填。手动输入模式的密钥可被同源脚本读取，并会进入高德请求；生产环境推荐下述服务端代理模式。探头数据要求服务器能访问进京365。关闭终端或按 Ctrl+C 停止服务。

首页为全屏地图，“附近”列表、“设置”和设置中的说明默认收起。定位及回到当前位置保留在地图上；范围、手动选点、数据刷新和密钥清除放在设置内。“路线”面板支持起终点选点与摄像头区域累积避让预览，尚未实现实时转向导航。

必须通过环境变量 `AMAP_KEY` 配置自己的 JS API Key。`localhost` / `127.0.0.1` 可用于本机定位；手机通过局域网访问或正式部署时应使用 HTTPS。正式域名需符合高德 Key 的域名白名单。

## 其他环境运行

需要 Node.js 20 或更高版本，无第三方 npm 依赖。

```sh
AMAP_KEY='你的高德 Web 端 JS API Key' AMAP_SECURITY_CODE='你的安全密钥' npm start
```

浏览器访问 http://127.0.0.1:3000。生产部署需使用 HTTPS，设置 `HOST=0.0.0.0` 并在高德控制台配置域名白名单。`PORT` 可修改端口。Key 使用自己的高德账号申请；安全密钥仅保存在服务端环境变量，前端通过 `/_AMapService/` 代理访问高德安全服务。确认高德服务额度、费用与使用条款。未配置 Key 时页面会显示地图加载失败。

有请求到达且缓存超过 10 分钟时，服务端尝试更新来源数据，手动刷新最短间隔 1 分钟，并发请求合并；失败时保留进程内最近一次成功的数据。重启后缓存会丢失。解析失败或记录数相对上次减少超过一半不会覆盖缓存。数据字段作为不可信文本处理，详情链接仅允许进京365域名。

### 自有服务器与免输入模式

在服务器创建 `/etc/jingtu/jingtu.env`，用 `.env.example` 中的变量名填入真实配置，文件属主设为 root、权限设为 `0600`。`AMAP_KEY` 必须是 Web 端 JS API Key，`AMAP_SECURITY_CODE` 必须是同一 Key 对应的安全密钥。由 systemd 加载该文件后，访客无需输入密钥。JS API Key 会按 SDK 要求发给浏览器；安全密钥由服务端代理附加，不由 `/api/config` 返回。不要将真实配置、SSH 私钥或服务器运维资料放入仓库。项目不自动加载本地 `.env`。

```sh

```

`worker.js` 是 Sites / Cloudflare Workers 后端，`build.mjs` 将页面资源与解析器打包到 Worker，运行 `npm run build` 输出 `dist/server/index.js`。`.openai/hosting.json` 保留现有站点标识。`server.js` 用于本地 Node 开发。两种后端均使用进程或 isolate 内存缓存，重启或回收后缓存会丢失；限频和并发合并仅在单实例内生效。

## 道路颜色

红色表示推测主路、高速或高架，黄褐色表示推测辅路、地面或匝道，灰色表示待确认。独立探头显示 12 像素小点，不再使用蓝色数字聚合圆。

当前范围内探头会串行查询高德逆地理编码（搜索半径 300 米），包含来源已有分类和带不确定备注的点；点击详情优先查询该点。每页最多 100 次，间隔 300 毫秒，超时 8 秒，结果仅在页面内缓存。需要高德地理编码权限及额度。详情展示附近道路名称、距离、方向、路口、地址及查询状态。仅考虑 40 米内名称匹配的道路作为分类线索，多条匹配道路或来源与高德线索冲突时保留待确认；不确定备注不会被自动覆盖，查询失败保留原有来源判断并提示核对未完成。

## 路口分组与方位标记

将当前查询范围内、距同一高德候选路口中心 100 米以内的至少两条记录合并成一个紫色罗盘点；距离固定，不提供调节选项，可关闭分组。普通探头继续使用原道路颜色的小点，不做数字聚合。缩小时路口点显示为 36 像素紫色小罗盘；放大到 16 级及以上时，罗盘展开为各成员原始坐标上的 12 像素小点，缩回 16 级以下恢复分组。中央数字是来源记录数，八个方位的紫色亮点表示该侧有匹配记录，空心表示暂无匹配记录，不能据此认为该方向没有设备。地图保持正北朝上。

保留逆地理编码的路口坐标和道路名称；相同道路组合、距固定代表点 25 米内的候选中心去重。每个摄像头分别匹配半径内的候选中心，不按摄像头彼此相邻的关系串联合并。名称同时包含两条候选道路时优先匹配；同级证据的前两名距离差不足 30 米时保持单点。缺少有效路口、查询失败且无其他可用候选、只有一个成员、来源明确描述高架上/桥上/高速/匝道/隧道/地下的记录均保持单点。单个查询返回的候选也可用于当前范围内其他点的距离推测，成员并不保证都完成了独立逆编码核对。

方位表示摄像头坐标在路口的哪一侧，不代表拍摄朝向或通行方向；采用八方位。中心 15 米内只使用来源明确写出的“路口北”等位置；无法判断时显示问号。点击路口点可查看成员方位、距路口距离，再进入原探头详情查看通行方向、道路类别和来源。分组仅包括当前查询范围内的记录，边界可能遗漏范围外的其他成员；随着高德查询完成或范围变化会更新。按用户要求固定为 100 米，尚未用真实样本标定准确率；来源坐标系、复杂立交和多个内部交叉点仍需核验。

“主辅路判断”和“高架 / 地面”分开展示。高德逆地理编码的附近道路不能确认探头实际所在车道或高架层级；仅来源明确写出高架上、桥下等时展示其层级描述并标注待核验。接口依据见[高德 Geocoder 文档](https://lbs.amap.com/api/maps-javascript-api/reference/geocode/geocoder)。

修改后端路由后需重启 Node 服务。若页面一直停在“正在加载地图”，检查 `/app.js`、`/road.js`、`/junction.js` 与 `/location.js` 是否均返回 JavaScript；旧进程可能仍使用旧路由。

若定位提示“坐标转换失败”，或高德道路查询持续失败，检查安全代理返回的 JSONP 是否被标为 `application/json` 并带有 `nosniff`；浏览器会阻止将其作为脚本执行。`amap-proxy.js` 会校验回调名及 JSONP 包装，将有效响应标为 JavaScript，同时保留 nosniff。Node 部署需包含该模块并重启服务，Worker 构建已内嵌此逻辑。

### 移动时更新位置

授权后通过 `watchPosition` 持续获取 GPS 位置，每次转换为高德坐标后同步刷新查询中心、附近探头、距离排序与地图标记；后续移动保持当前缩放级别。手动选点暂停跟随，点击“重新定位”或“回到当前位置”恢复。切回页面会重新请求新位置。定位失败或超过 30 秒未收到更新会提示当前显示的是上次位置附近的探头。浏览器后台或锁屏可能暂停定位，实际频率与精度取决于设备、权限和信号；探头来源数据仍遵循原有缓存策略，并非实时探头数据源。
